1. 这个工具做什么

把一个数据目录整棵树搬到另一个盘，并在原路径上留下一个链接。 迁移之后，原来的路径依然存在、程序照常按原路径访问，但实际数据已经在新盘上。

典型用途：

  • C 盘空间不足，把某个软件的数据目录挪到 D 盘、E 盘
  • 换硬盘：把整块盘上的数据目录搬到新盘
  • 把巨大的缓存/素材/模型目录挪到容量盘，同时不想改任何软件的配置
和「剪切粘贴」的区别：剪切粘贴之后原路径就没了，任何按原路径找数据的程序都会报错。 这个工具在最后一步会把原路径做成链接，所以两边都能继续用。

迁移分四步，工具在每一步都尽量先验证、再动手：

1) 复制     把整棵树复制到目标盘（不动源）
2) 校验     逐个文件比对，确认目标端完整
3) 改名     把源目录改名成「备份」（这一步会失败——如果有程序占着它）
4) 建链接   在原路径上建一个指向目标的链接
第 3 步是最容易失败的地方。只要有任何程序打开了源目录里的任何文件 （哪怕只是资源管理器开着那个文件夹），改名就会失败——而此时复制和校验都已经跑完， 用户已经等了几个小时。所以工具要求在开始之前先做一次检验（见 4.4）。

2. 运行与启动

解压压缩包，双击里面的 Windows数据迁移助手.exe。不需要安装，也不需要管理员权限。

什么时候需要管理员说明
源树里有文件符号链接 Windows 默认只允许管理员创建文件符号链接。目录链接（junction）不需要。 计划页会提示，并可点「以管理员身份重试」。
有无权限访问的目录 计划页会列出它们。可选择跳过，或提权后「接管这些目录的权限」（会记录原始 ACL，回滚时还原）。

3. 界面总览

顶部是品牌栏与步骤条，底部是状态行（显示当前正在做什么、以及最近一次操作的结果）。

四个步骤：选择目录 → 确认计划 → 执行迁移 → 完成。

4. 第一步：选择目录

4.1 源目录

要搬走的那个目录。可以点「浏览…」选择，也可以直接把文件夹拖进输入框。

源目录可以就是某个盘符根吗？不可以——工具会拒绝，因为没法给盘根建链接。

下面这些系统目录本身也会被拒绝（不是 bug，是刻意的保护）：

  • C:\Windows 以及它里面的任何一层（系统路径写进注册表的地方太多，搬走哪个都可能开不了机）
  • C:\Program Files 与 C:\Program Files (x86)
  • C:\ProgramData
  • C:\Users 以及 C:\Users\<你的用户名> 这一层
只拦"本身"，不拦它们的子目录——下面这些正是本工具要服务的对象，都能正常迁移： C:\Program Files (x86)\某游戏、C:\Users\你\AppData\Local\某缓存、 C:\ProgramData\某应用\cache。

为什么要拦：一是把它们整体搬走会让依赖它们的安装、更新、卸载行为异常； 二是「开始检验」那一步会真的给源目录改名再改回，而系统目录改名会牵动 WOW64 重定向、兼容性数据库与安全软件的过滤驱动同时重新评估整棵子树——表现就是卡死。

4.2 目标目录

数据要搬到的地方。它会成为源目录的「新家」。

  • 目标目录不存在时会新建；
  • 目标目录已存在且非空时会按「合并/续传」处理——这一点在计划页会有明确说明；
  • 源目录不能套在目标目录里，反之亦然（工具会拦下来）。

4.3 剩余空间

两个路径右侧各显示所在卷的剩余空间，用于对照计划页算出的「所需空间」。这张盘剩余不足时， 计划页会给出提示。

4.4 开始检验 必须做

右上角的「开始检验」按钮做两件事：

  1. 前置检查——源/目标是否存在、是不是链接、有没有互为子目录、同盘、空间是否够；
  2. 试探改名——把源目录改名再立刻改回来（几毫秒），用来回答那个最关键的问题： 现在有没有程序占着它。
为什么必须检验：改名失败是唯一一个「等到最后一步才炸」的错误。复制校验全过、 用户等了几个小时，才卡在改名上。试探改名把这个风险提前到几毫秒内暴露。

「开始扫描」在检验通过之前是灰的——没有检验就没有结论，就不放行。

检验的副作用（按钮的悬停提示里也写了）：源路径会消失几毫秒， 正开着这个目录的程序可能报「文件夹已删除」。这是正常的，改回来了。

检验结果分四种状态：

状态显示能否继续
尚未选择目录中性指引不能
选好了但还没检验中性指引，明确提示去点「开始检验」不能
检验通过绿色说明；可能同时有黄色警告能
有问题逐条列出看颜色

红色与黄色的区别

  • 红色 · 错误 会禁止进入下一步。 例如：源目录不存在、源目录是链接、源目录无法改名、空间不足。
  • 黄色 · 警告 不拦，只是让你知情。 例如：源和目标在同一个卷（迁移不会释放空间，且备份与原件同盘）。

4.5 找出占用进程 按需出现

只有检验因「源目录无法改名」失败时，卡片上才会多出一个 「找出占用进程 →」按钮。别的错误（源不存在、空间不足）不会出现它—— 那些问题在这一页解决不了。

点它直接跳到子页面，详细说明见第 5 节。

5. 找出占用进程（子页面）

这不是向导的第 5 步，而是第一步的子流程：步骤条仍然停在「选择目录」， 办完点左下角的「← 返回选择目录」，工具会自动重跑一次检验。

5.1 扫描的两个阶段

  1. 缩小范围——逐个试探源目录的子目录，找出哪几棵子树被占着； 这一步很快。顺带说明：试探只针对子目录，平铺的普通文件不试探—— 试一个文件约 0.67 毫秒，而直接让系统扫它只要 0.13 毫秒，试它反而更慢。
  2. 扫描占用——只对嫌疑子树问系统「谁占着这些文件」。这一步的进度条按文件数走。
如果源目录顶层条目特别多（超过 2000 个，例如整个目录平铺了一堆文件）， 工具会跳过第一阶段直接扫整棵树，并在说明行里告诉你原因——逐个试探那时比直接扫还慢。

5.2 占用者表格

列含义
进程程序名
PID进程号
可执行文件完整路径——用来确认「这到底是哪个程序」，光看名字可能认不出
状态可由本工具关闭 或 不关闭

5.3 关闭这些程序

按钮上会写明要关几个（例如「关闭这 1 个程序」）。点下去走的是系统官方的关闭通道 （和安装程序让你「关闭以下程序以继续」是同一个机制）：程序会走正常退出流程， 该提示保存的还会提示保存。

为什么没有「只关其中几个」的勾选：底层接口是整批的，做不到逐个选择。 想少关几个，请先自己手动关掉，再点「重新扫描」。

5.4 工具不会关闭哪些程序

下面这些进程即使占着文件，工具也不动手，并且会说明理由，请你手动处理：

类别例子理由
系统关键进程System、smss、csrss、 wininit、winlogon、services、lsass、 svchost关掉会蓝屏、重启、注销，或连带一批系统服务
桌面外壳explorer.exe、dwm.exe 关掉会让桌面、任务栏和所有已打开的文件夹消失；整个屏幕显示异常
安全软件MsMpEng.exe、NisSrv.exe、 SecurityHealthService.exe关掉会让电脑失去实时防护
工具自己本程序及其父进程链关掉会把工具自己带走
身份不明取不到可执行文件路径的进程证明不了它是什么，就不能假设它安全
只要批次里混进一个受保护进程，工具就一个都不关。 底层关闭接口是整批生效的——放行就等于把 explorer 之类一起关掉。 所以宁可这一次不动手，把「为什么不动」原样告诉你。

5.5 强制结束

只有在关闭请求发出去之后没成功时才会出现这个按钮。它会单独弹窗确认一次， 并明确警告：程序里未保存的内容会直接丢失，正在写盘的数据可能损坏。

被 5.4 的名单挡下时不会给这个按钮——强制走的是同一条路，一样会被拦， 给了就是个按不动的死按钮。

5.6 重新扫描

手动关掉程序、或关了一部分之后，点它重新查一遍。扫描结束前后，「重新扫描」按钮始终可用。

5.7 「改不了名，但查不出占用者」是怎么回事

有一种占用查不到具体进程：程序把源目录本身当作工作目录。 典型情况是：

  • 资源管理器正开着这个目录（或它的父目录）
  • 有个终端 cd 在里面

这类占用挡得住改名，但拿不到进程号。工具会如实说明这一点，你手动关掉那些窗口再重新扫描即可。

关完之后：工具会重新做一次改名试探——能改名才算解决。 只有这时才会显示绿色的「占用已解除」。如果返回码说失败、但实际已经能改名， 也会如实报「已解除」（系统那个接口会返回「部分成功」，容易被误读成失败）。

6. 第二步：确认计划

扫描完成后进入这一页。它不改动任何东西，只把将要发生的事摊开给你看。

6.1 迁移计划

页面最上方是一排关键指标：

指标含义
真实数据量要搬走的总字节
文件数 / 目录数这棵树里有多少个文件与目录
链接数树里有多少个链接（它们的外部数据不会被复制，只重建链接）
需提权目录有多少个目录当前权限访问不了
被占用迁移前不做全树预扫（那要对每个文件问一次系统）。真正的占用检测在 执行时做，失败会列进报告的未完成清单
预计耗时按本次扫描的实测速度估算

6.2 计划摘要

源目录、目标目录、目标盘剩余空间。若目标盘不够会明确提示；若目标目录已存在且非空， 这里也会说明将按「合并 / 续传」处理。

6.3 链接目标归位表

源树里的链接（junction / 符号链接）不会把外部仓库的数据复制过来—— 只重建链接本身。但如果链接指向的仓库也在被搬的范围内，就需要改写链接的指向。

多数情况这张表留空就行：只有那些目录原来的位置以后不再存在时才需要填。

列含义
链接目标目录链接现在指向哪里
链接数有多少个链接指向这里
重写为可编辑。留空表示不重写，保持原指向
迁移后指向按你填的内容，实时算出迁移后这个链接会指向哪里

6.4 怎么用「重写为」

假设源树里有 node_modules 指向 E:\npm-cache，而 E:\npm-cache 这次也要一起搬。目标端重建链接时如果还写 E:\npm-cache，那它指的就不再是你这份数据的副本了。

在「重写为」里填目标端对应的新位置（例如 F:\npm-cache）， 「迁移后指向」这一列会立刻告诉你结果对不对。填错了随时改。

6.5 应用映射并重新扫描

改完映射后点它重新扫描一遍，让计划和摘要按新映射重算。这一趟通常很快。

6.6 无权限目录与提权

按钮什么时候可用做什么
以管理员身份重试重建文件符号链接需要特权时 以管理员身份重新启动本工具
接管这些目录的权限确实有无权限目录，且已经是管理员 对这些目录执行接管属主与授权。会先把原始 ACL 记进会话，回滚时还原

6.7 非链接类重解析点

这一类条目既不是链接，也不是普通文件或目录：云占位符（OneDrive 按需文件， 本地只有一个指针、内容在云端）、AppExecLink（应用商店应用的执行别名）、 Dedup（服务器去重）等。它们背后都有真实数据。

默认按真实内容复制——能直读的读出来（云占位符会触发下载， 可能很慢、很占流量），读不动的把重解析数据原样搬过去。

选项默认说明
跳过下列条目，不按真实内容复制 关 勾选后这些条目完全不复制，只留在备份里。 源目录删除后备份就是唯一副本，而备份通常也会跟着被删—— 请先确认它们确实不再需要。

6.8 复制选项

选项默认说明
启用 SHA256 全量校验
（较慢）		 关 默认已比对大小与时间戳。开启后会逐个文件算哈希，能进一步发现 「大小和时间戳都相同、内容却已损坏」的文件。数据量大时明显变慢。
跳过无权限访问的目录 关 这些目录只保留在备份里，复制不到目标端。 不勾选时会因权限问题报错停下。
上面两个「跳过」的共同点：被跳过的内容只存在于备份里。 「删除备份」会让它们永久消失。报告页对此有明确警告。

7. 第三步：执行迁移

7.1 进度区

显示整体进度、当前文件、速度、预计剩余时间、已复制文件数，以及实时日志。

7.2 暂停 / 取消

按钮行为
暂停 / 继续当前文件复制完之后停下，可随时继续。已复制的内容保留
取消点下后按钮变为「正在停止…」并禁用，走到下一个检查点就停。 已经复制的内容会保留，下次可接着来
取消不等于前功尽弃。工具会记录已完成与失败的每一个文件； 重新启动后选中同一个会话，会从断点继续（已完成且未改动的文件会跳过）。

7.3 失败清单

列出没能复制的文件和原因（相对路径 / 原因 / 占用进程）。 「原因」会写清楚是文件被占用、还是读写错误；被占用时还会列出占用它的进程。

7.4 打开日志文件

用资源管理器定位到日志文件。日志记录整趟迁移的每一步，出问题时它是最重要的排查依据。

日志与会话文件都在：

%LOCALAPPDATA%\DataMigrationTool\sessions\
    <会话 ID>.json     结构化数据（阶段、统计、链接清单）
    <会话 ID>.done     已完成文件的清单（用于断点续传）
    <会话 ID>.log      完整运行日志

8. 第四步：完成（报告页）

8.1 统计

项含义
成功复制（个）成功复制的文件数
成功复制（字节）成功复制的总字节
跳过（已存在）目标端已有、且大小与时间戳一致的文件（续传时常见）
复制失败没能复制的文件数（非零会标红）
校验缺失目标端缺少的文件数（非零会标红）
校验不一致源与目标内容不一致的文件数（非零会标红）
断链（原样重建）本来就指向不存在位置的链接——工具照样原样重建，列出来让你知道

8.2 未完成清单

把「没做完的事」汇总成一张表。四列分别是：类别（未复制 / 缺失 / 不一致 / 断链 / 链接重写 / 目录时间戳 / 未保留属性 / 未完成步骤）、相对路径、 原因、占用进程。这一页和导出的 CSV 内容一致。

表是空的，说明这一趟没有遗留问题。

8.3 备份警告

只要备份还在，报告页顶部就有一条红色警告，写明备份在哪，并强调：

回滚必须依靠备份文件。删除备份后将无法再进行回滚——「一键回滚」会直接失败，
源路径也就回不到迁移前的状态了。确认不再需要退回迁移前的状态，再用本页的「删除备份」。

判据是「你是否确定不再需要退回迁移前的状态」，不是「是否已经手动验证过」。 这条警告在备份被删除或回滚成功之后会自动消失。

8.4 导出 CSV

把当前这一页的内容导出成 CSV，用于存档、报修或转给别人看。 在恢复态（见 8.8）导出的是恢复信息，不是迁移报告。

8.5 重新校验

再做一遍完整性比对。用途：迁移之后又往目标端写过东西，想确认没被破坏。
注意：回滚之后这个按钮会禁用——那一刻源是刚还原回来的原件、 目标端是清空或半残的副本，两边早已不是同一次搬迁的两端，比出来的全是假的缺失。

8.6 删除目标

目标端只留下半成品、你确认不需要了时的清理出口。会弹窗确认，并说明源目录不受影响。

8.7 一键回滚

退回迁移前的状态：把备份改回原名、恢复真实目录。

回滚前会弹窗确认，并带一个默认不勾选的选项：

同时删除目标端里同步过去的内容（迁移之后写进去的东西不会被删）
  • 不勾：只还原源路径，目标端那份原样留着；
  • 勾上：把目标端里同步过去的内容清掉，但目录本身保留—— 「迁移之后新写进目标端的东西」不会被动。
回滚必须有备份。如果备份已经被删除，回滚会被拒绝并说明原因。

8.8 删除备份 不可逆

删除源数据在备份里的最后一份副本。确认弹窗会明确写出：删掉之后就无法再回滚了。

有一种情况是删不掉的：备份里含有「只存在于备份里」的内容 （被跳过的条目、被排除的目录）。工具会说明原因，并再问一次 「仍要强制删除吗」——请先确认那些内容确实不再需要。

请勿在不确定的情况下删除备份。 判据是「你是否确定不再需要退回迁移前的状态」，而不是「是否已经手动验证过」。 回滚必须依靠备份文件；删除备份后将无法再进行回滚。

8.9 回滚之后：页面会变成「恢复态」

回滚成功后，报告页会从「迁移结果」切换成「恢复结果」，因为那件事已经被撤销了：

  • 标题变成「恢复成功」，统计网格与未完成清单隐藏；
  • 改为列出四项恢复信息：源目录（是否已恢复为真实目录）、 备份（是否已改回原名）、目标端（已清空／保留未清／未清理／本就不存在）、 权限（接管过的权限是否已还原）；
  • 「导出 CSV」导出的是这份恢复信息；
  • 「一键回滚」与「删除备份」禁用（备份已经不存在了），「删除目标」按需可用。

10. 数据安全须知

10.1 迁移的四步，以及每步失败会怎样

阶段做了什么失败了会怎样
1 复制把整棵树复制到目标端，源一动不动 源完好，目标端留半成品，可清理或重来
2 校验逐个文件比对目标端是否完整 同上，报告页会列出缺失/不一致的文件
3 改名源目录改名为 <源名>.bak_<时间戳> 源仍在原路径上，什么都没变。关掉占用它的程序后重试即可
4 建链接在原路径建一个指向目标端的链接 源已经在备份名下，工具会停在这里并告诉你备份在哪

10.2 备份是什么、放在哪

备份就是改名之后的源目录，与源目录同级，命名形如：

C:\a\wwwwww            ← 源目录
C:\a\wwwwww.bak_20261012143012   ← 备份（迁移成功后，原路径上是链接）

它是你退回迁移前状态的唯一依靠。

10.3 中断了怎么办

会话会持续写到 %LOCALAPPDATA%\DataMigrationTool\sessions\。 界面重新进入时选中同一个会话即可继续；命令行用 resume <会话>。 已完成且未被改动的文件会跳过。

10.4 什么情况下回滚还能做

  • 备份还在；
  • 源路径当前是链接（也就是迁移确实完成了）；

两条不满足时工具会拒绝回滚，并说明原因——它不会在没有退路的情况下动手。

11. 已知限制

限制说明与影响
目录句柄占用查不出进程 有程序把源目录本身当工作目录（资源管理器开着它、终端 cd 在里面）时， 改名会被挡住，但系统接口拿不到那个进程。界面会如实说明并让你手动关。
稀疏文件会变实占 稀疏文件（例如动态 VHD）复制到目标端后会占用完整大小。 计划页的空间需求是按逻辑大小算的，与之一致，不会中途才告诉你空间不够。
占用扫描在超大目录上耗时较长 扫描成本约每文件 0.13 毫秒。几十万文件时需要等，进度条会显示进展。
非链接类重解析点默认按真实内容复制 某些特殊重解析点（非 junction/符号链接）默认按内容复制； 也可在计划页勾选跳过，跳过的只保留在备份里。
同盘迁移不释放空间 源与目标在同一个卷时，迁移不会释放空间，而且备份与原件同盘—— 这张盘出问题两边一起丢。工具会用黄色警告提示这一点。

12. 常见问题

为什么非要我先点「开始检验」？

因为「源目录能不能改名」是唯一一个会等到最后才暴露的错误。检验里那一次几毫秒的 试探改名，能在你等几个小时之前就把这个问题问出来。

迁移大概要多久？

主要取决于数据总量和磁盘速度。小文件多时（几万个）主要花在每文件的系统调用上； 大文件多时受磁盘带宽限制。执行页会实时显示速度和预计剩余。

中途取消了，白干了吗？

没有。已完成的文件都记在会话里，重新选中同一个会话会从断点继续， 已完成且未改动的文件直接跳过。

目标目录里已经有同名文件怎么办？

工具会按「合并/续传」处理：已完成且大小与时间戳一致的文件跳过，其余覆盖。 目标端「不属于这次迁移」的内容不会被删——回滚时清目标端也会先检查这一点。

源目录里的快捷方式/链接会被复制过去吗？

不会复制它指向的数据——只在目标端重建链接本身。 这是有意为之：链接指向的外部仓库不该被搬两遍。如果那个仓库也在搬迁范围内， 用计划页的「重写为」把链接指向改成新位置。

提示无权限访问怎么办？

两种选择：勾选「跳过无权限访问的目录」（它们只保留在备份里）， 或者以管理员身份重试后点「接管这些目录的权限」——工具会先把原始 ACL 记进会话， 回滚时还原。

工具关掉了别的程序，会不会弄丢我没保存的东西？

「关闭这些程序」走的是系统官方的关闭通道，程序会走正常退出流程， 该提示保存的会先提示保存。只有「强制结束」才会直接丢未保存内容， 而它需要单独确认。

我把备份删了，还能回滚吗？

不能。回滚必须依靠备份文件。删除备份时工具会明确写出这一点并要求确认。

为什么工具不肯关闭某个程序？

见 5.4 的名单。每一类都会写明理由。这些程序要么关掉会导致系统层面的事故， 要么关掉会让工具自己消失，要么无法确认它到底是什么。请手动处理。

本说明书对应 Windows数据迁移助手 1.0.0。 界面文案以实际程序为准。
